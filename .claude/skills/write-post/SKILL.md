# 블로그 글 작성

사용자가 준 글감을 이 블로그의 스타일에 맞는 완성된 글로 작성한다.

## 절차

1. **글감 파악**: `$ARGUMENTS` 또는 대화에서 글감을 확인한다. 글감이 없으면 무엇에 대해 쓸지 물어본다. 글감이 코드/파일/경험담이면 필요한 만큼 관련 파일을 읽고 사실을 확인한다 — 추측으로 기술 내용을 지어내지 않는다.
2. **기존 글 확인**: `posts/`의 최근 글 1–2개를 읽어 문체를 맞춘다.
3. **작성**: 아래 스타일 가이드에 따라 글을 쓴다.
4. **저장**: `posts/<영문-kebab-case-슬러그>.md`로 저장한다. 슬러그는 내용을 요약한 짧은 영어 단어 2–4개 (예: `debugging-vite-hmr.md`). 기존 파일과 겹치지 않는지 확인한다.
5. **보고**: 파일 경로와 제목, 한 줄 요약을 사용자에게 알리고, 수정하고 싶은 부분이 있는지 확인한다. 커밋/푸시는 사용자가 요청할 때만 한다.

## Frontmatter (필수 계약)

세 필드 모두 반드시 채운다. `title`이나 `date`가 없으면 홈 목록에서 누락된다.

```md
---
title: 글 제목
date: YYYY-MM-DD   # 오늘 날짜
description: 홈 목록에 보일 한 줄 설명. 마침표로 끝낸다.
---
```

- `title`: 한국어, 낚시성 없이 내용을 그대로 말하는 제목. 문장형도 좋다 (예: "이 블로그는 이렇게 만들었습니다").
- `description`: 글의 핵심을 한 문장으로. 제목 반복이 아니라 보완.

## 본문 스타일

- **언어·어조**: 한국어 존댓말("~합니다", "~어요" 혼용 가능). 담백하고 실용적인 톤. 과장·감탄사·이모지 금지.
- **구조**: frontmatter 바로 아래 `# 제목`(frontmatter title과 동일)으로 시작. 이어서 도입 문단 1–2개, 그다음 `##` 섹션 2–4개. `###` 이하는 꼭 필요할 때만.
- **분량**: 짧게. 핵심만 담아 대략 300–800 단어. 글감이 얇으면 억지로 늘리지 않는다.
- **문단**: 2–4문장의 짧은 문단. 목록·번호 리스트를 적극 활용하되 리스트만으로 글을 채우지 않는다.
- **코드**: 코드가 글감이면 언어 태그를 붙인 코드 블록으로 핵심 부분만 발췌. 전체 덤프 금지.
- **링크**: 내부 링크에는 `.html` 확장자를 붙이지 않는다 (`cleanUrls: true`).
- **구분선 금지**: 본문에 `---`(수평선)를 쓰지 않는다. 테마가 `##` 제목 위에 경계선을 자동으로 그리므로 줄이 두 개 겹쳐 보인다. 외부 원고를 그대로 옮길 때도 `---`는 제거한다.
- **마무리**: 짧은 정리나 다음 계획 한두 문장으로 끝낸다. "읽어주셔서 감사합니다" 류의 상투적 맺음말 금지.

## 하지 말 것

- AI가 쓴 티가 나는 표현: "~에 대해 알아보겠습니다", "결론적으로", 과도한 볼드, 섹션마다 요약 반복.
- 글감에 없는 사실을 지어내기. 확인 안 된 내용은 쓰지 않거나 사용자에게 물어본다.
- `posts/` 밖에 저장하거나 frontmatter 필드를 빠뜨리기.
